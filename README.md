# Farm Postman — Postman AI Gateway Research & Automation

> Reverse-engineering the Postman AI backend (Postbot / Agent Mode) and automating account provisioning to expose a useable AI gateway. Built for **research & interoperability** purposes.

## 📌 Overview

This project documents a full deep-dive into **Postman's AI infrastructure**: how account signup works, how the runtime agent authenticates, and where the real AI (Postbot / Agent Mode) endpoints live. The end goal is a clean, **OpenAI-compatible gateway proxy** in front of Postman's AI backend so it can be consumed by any other AI agent.

### What was reverse-engineered

| Area | Result |
|------|--------|
| **Account provisioning** | Full signup → email verification → workspace onboarding, automated |
| **Auth (runtime)** | `ra.gw.postman.com/v1/handshake/token` + `runtime-agent.getpostman.com` — issues short-lived JWT runtime tokens |
| **AI service surface** | `/_api/ws/proxy` with `service: "ai"` — confirmed **live** (`/ai/user-settings` returns 200 with feature flags) |
| **Chat endpoint** | `service:"ai"` → `POST /ai/postbot/request/completions` (requires `body.configs.intellisense.components`) |
| **Agent mode protocol** | `orion-http.gw.postman.co` + `cloud-agent.gw.postman.com/ws` (WebSocket) |
| **Streaming** | `/ai/postbot/request/completions/{id}/accept` |

## 🏗️ Architecture

```
┌──────────────┐     turnstile (headless)     ┌──────────────────────────────┐
│ FlashMail    │ ───────────────────────────▶ │    Postman Signup Flow       │
│ (temp inbox) │                              │  identity.getpostman.com     │
└──────────────┘                              └──────────────┬───────────────┘
                                                            │ verify email (OTP)
                                                            ▼
                                        ┌────────────────────────────────────┐
                                        │  Authenticated Workspace Session    │
                                        │  <username>-<id>.postman.co         │
                                        └──────────────────┬─────────────────┘
                                                           │ cookies
                      ┌────────────────────────────────────┼──────────────────────┐
                      │                                    │                      │
                      ▼                                    ▼                      ▼
             ra.gw.postman.com                     /_api/ws/proxy          runtime-agent.getpostman.com
             handshake/token          {service:"ai", path:"/ai/..."}      handshake/token (agent=CLOUD/WS)
                      │                        │   (AI endpoints)                  │
                      ▼                        ▼                                  ▼
             cloud-agent / WS          orion-http.gw.postman.co          Agent Mode WS / HTTP
             (Agent Mode)              /v1/request                       (desktop runtime)
```

**Key insight:** Postman's AI is fronted by **bifrost** (`bifrost-https-v4.gw.postman.com`) and proxied through the workspace domain `/_api/ws/proxy`. Auth is cookie-based (`.postman.co` session) + a runtime JWT for agent calls.

## 🔐 Authentication Chain

The AI gateway session is established through this chain:

1. **Bootstrap session** — via `identity.getpostman.com/signup` (called from the app/`/_api` and carrying `X-CSRF-Token` + `X-Turnstile-Token` headers).
2. **Email verification** — OTP code delivered to the registered inbox, submitted on the verify-account page (which also requires a Turnstile solve).
3. **IAM + session cookies** issued:
   - `postman.iam.sid` (`.id.gw.postman.com`)  ← main IAM token
   - `postman.sid`, `getpostmanlogin`, `dashboard_beta` (`.postman.com` / `.postman.co`)
4. **Runtime agent token** — `GET ra.gw.postman.com/v1/handshake/token?agent=CLOUD|WS` returns a JWT with claims:
   ```json
   { "aud": ["cloud-agent", "packman"], "userId": 57742627, "teamId": 36285176, "requestTimeout": 30 }
   ```

> ⚠️ **Security note:** The IAM/session cookies and the runtime JWT are **sensitive**. Never commit them. See `.gitignore`.

## 🧭 Endpoints Discovered (RE)

### Signup / Identity
```
POST https://identity.getpostman.com/signup
  Headers: X-CSRF-Token, X-Turnstile-Token
  Body:    { email, username, password, autogeneratedUsername, terms:{accepted:true} }

GET  https://identity.getpostman.com/verify-account   (OTP submit, + Turnstile)
POST https://identity.getpostman.com/login
```

### AI / Runtime Gateway
```
GET  https://ra.gw.postman.com/v1/handshake/token?agent=CLOUD|WS   → runtime JWT
GET  https://runtime-agent.getpostman.com/v1/handshake/token?agent=CLOUD|WS

POST https://<workspace>.postman.co/_api/ws/proxy
  Body: { "service":"ai", "method":"GET", "path":"/ai/user-settings" }   ✅ LIVE (200, feature flags)

POST https://<workspace>.postman.co/_api/ws/proxy
  Body: {
    "service":"ai","method":"POST",
    "path":"/ai/postbot/request/completions",
    "body":{
      "configs":{ "intellisense":{ "components":["PARAMS","HEADERS","BODY"] } },
      "messages":[{ "role":"user", "content":"..." }],
      "model":"gpt-5.6-sol"
    }
  }

POST https://<workspace>.postman.co/_api/ws/proxy
  Body: { "service":"ai","method":"POST","path":"/ai/postbot/request/completions/{id}/accept", ... }  (stream)

POST https://orion-http.gw.postman.co/v1/request      (Agent Mode runtime; auth: Bearer <runtime token>)
WS   wss://cloud-agent.gw.postman.com/ws              (Agent Mode WebSocket)
```

### Public gateway (bifrost)
```
POST https://bifrost-https-v4.gw.postman.com/ws/proxy
  Same {service, method, path, body} envelope. Requires `configs` for AI POSTs (injected server-side from cookie auth).
```

> 🔬 **Validation chain recovered from server 400s:**
> `configs` required → `configs.intellisense` → `configs.intellisense.components` → `must be one of [PARAMS, HEADERS, BODY]` → (next) `context` required.

## 📦 Included Tooling

| Script | Purpose |
|--------|---------|
| `robust_full.py` | One-shot automated signup: FlashMail inbox → signup → Turnstile (headless) → OTP verify → workspace, dumps full session cookies. |
| `part1_auth.py` | Step 1 — CloakBrowser auth → dump fresh cookies (no curl_cffi import to avoid greenlet collision). |
| `part2_handshake.py` | Step 2 — `curl_cffi` handshake to get the runtime JWT from fresh cookies. |
| `postman_proxy.py` | OpenAI-compatible gateway skeleton (`/v1/chat/completions` + `/v1/models`). |

### Setup

```bash
# 1. Dependencies
pip install curl_cffi cloakbrowser    # + local captcha-solver (Turnstile) at ./captcha-solver

# 2. Configure FlashMail credentials (disposable inbox API)
export MAIL_API="https://mail.flashdev.org/api/public/v1"
export MAIL_API_KEY="cmf_v1_your_key_here"

# 3. Farm a session
python robust_full.py  user@temp.com  username  'Password!123'
#   → produces robust_result.json with full cookies

# 4. Get runtime token
python part2_handshake.py robust_result.json
#   → GET ra.gw.../handshake/token  → 200 { "token": "..." }

# 5. Run the OpenAI-compatible proxy
python postman_proxy.py --cookies robust_result.json --port 9120
#   curl http://localhost:9120/v1/models
```
